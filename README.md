# halyk-agent

Агент для Halyk AI Challenge. Читает корпус обезличенных финансовых PDF и реестр транзакций и
по каждому финансовому ковенанту каждого заёмщика определяет три вещи:

| Поле | Что это |
|---|---|
| `status` | `COMPLIANT` или `BREACH` |
| `actual` | фактическое значение показателя, который ограничивает ковенант |
| `evidence_txn_id` | единственная транзакция, определяющая результат, или `null` |

Результат — `out/submission.json` по форме `data/submission_template.json`.

**Как это устроено внутри — [ARCHITECTURE.md](ARCHITECTURE.md):** принцип разделения LLM и
детерминированного движка, поток данных по фазам, файловая иерархия, ответственность каждого
пакета и поведение при сбоях. Там же
[приёмка прогона на незнакомых документах](ARCHITECTURE.md#приёмка-прогона-на-незнакомых-документах)
— что смотреть, когда локального скора нет.

## Quick Start

Всё, что нужно снаружи, — датасет в `data/`, ключ в `.env` и Docker. Poppler и tesseract с
языками `rus`/`eng`/`kaz` уже внутри образа.

```bash
cp .env.example .env      # и вписать LLM_API_KEY, TEAM, CONTACT_EMAIL
mkdir -p .cache artifacts out logs
docker compose run --rm agent run
```

`mkdir` не формальность: контейнер работает от uid хоста, а недостающий каталог под bind-mount
docker создаёт сам и от root — в такой прогон стадия упирается на первой же записи.

На выходе — `out/submission.json`, `out/report.pdf` и остальное в `out/`.

Отдельная стадия вместо всего конвейера:

```bash
docker compose run --rm agent evaluate
docker compose run --rm agent score
```

Тома в `compose.yaml` не декоративные: `.cache/` держит кэш ответов модели, и без него каждый
прогон уходит в сеть заново — это ~330 вызовов и вся суточная норма free tier. `data/`
монтируется только на чтение.

Без compose:

```bash
docker build -t halyk-agent .
docker run --rm --env-file .env \
  -v "$PWD/data:/app/data:ro" \
  -v "$PWD/.cache:/app/.cache" \
  -v "$PWD/artifacts:/app/artifacts" \
  -v "$PWD/out:/app/out" \
  -v "$PWD/logs:/app/logs" \
  halyk-agent run
```

## Запуск без контейнера

```bash
go build -o bin/halyk-agent ./cmd/halyk-agent

bin/halyk-agent llm-check    # проверить ключ, модель и обвязку провайдера одним запросом
bin/halyk-agent run          # весь конвейер: ingest → … → report
```

`run` доводит прогон до `out/submission.json` при любом исходе и печатает список деградировавших
стадий; код возврата ненулевой, если деградировала хоть одна.

Стадии по отдельности — каждая продолжает с того, что оставила предыдущая:

```bash
bin/halyk-agent ingest      # фаза 0 — леджер, шаблон, текст всех PDF (без LLM)
bin/halyk-agent triage      # фаза 1 — тип документа и его заёмщик
bin/halyk-agent covenants   # фаза 2 — CovenantSpec на каждый пункт + критик
bin/halyk-agent facts       # фаза 3 — корректировки аудитора, стороны, курсы
bin/halyk-agent classify    # фаза 4 — категория и связанность на каждой строке
bin/halyk-agent evaluate    # фазы 5-6 — движок, evidence, критик по ячейкам
bin/halyk-agent submit      # фаза 7 — заполнение шаблона
bin/halyk-agent report      # фаза 8 — out/report.pdf (без LLM)
```

Вспомогательные команды:

```bash
bin/halyk-agent specs P1     # спеки заёмщика рядом с текстом пункта — для ручной сверки
bin/halyk-agent labels P1    # размеченный леджер: итоги по категориям и все строки
bin/halyk-agent validate     # проверка submission против шаблона
bin/halyk-agent score        # локальный скоринг против ground_truth.json (только отладка)
bin/halyk-agent stability    # сколько ячеек держится при повторных прогонах модели
bin/halyk-agent status       # что уже лежит в сторе
bin/halyk-agent version      # сведения о сборке
```

## Стек

**Go 1.26**, один статический бинарник на 21 МБ: `CGO_ENABLED=0`, SQLite чистый Go, шрифты
отчёта вшиты. Внешней СУБД не требуется.

| Библиотека | Зачем |
|---|---|
| `spf13/cobra` | команды и флаги |
| `modernc.org/sqlite` | стор без cgo |
| `shopspring/decimal` | деньги; арифметика ковенантов идёт только через него |
| `tidwall/gjson`, `sjson` | заполнение шаблона с сохранением порядка ключей |
| `go-pdf/fpdf` | финальный PDF-отчёт |
| `golang.org/x/sync` | ограничение параллелизма стадий |

**Внешние программы**, вызываются из `ingest`:

- **poppler** — `pdftotext` (текстовый слой), `pdftoppm` (рендер страниц);
- **tesseract** с языками `rus`, `eng`, `kaz` — страницы без текстового слоя читаются только OCR.

В образе они уже стоят; при запуске без контейнера ставятся пакетным менеджером системы.

## Модель

Одна модель на все стадии, по умолчанию **`gemini-3.5-flash-lite`** через OpenAI-совместимый
эндпоинт Gemini. Она же попадает в поле `model` файла submission.

Клиент говорит на `/chat/completions`, поэтому провайдер меняется тремя переменными —
`LLM_API_KEY`, `LLM_BASE_URL`, `MODEL` — без правки кода. Отличия слоёв учтены: Gemini не
принимает `seed`, а `reasoning_effort` у flash-lite отсутствует.

Модель вызывается шесть раз в разных ролях: триаж документа, извлечение ковенанта, критик
спеки, извлечение факт-базы, разметка описаний, критик готовой ячейки. Ни одна из ролей не
возвращает вердикт и не складывает числа — это делает движок на Go.

`temperature` всюду нулевая. Один прогон детерминирован и без этого: ответы кэшируются по хешу
промпта, поэтому повтор идёт из кэша.

## Что нужно на входе

Датасет кладётся в `./data` (или в каталог из `DATA_DIR`):

```
data/
├── documents/                    все PDF датасета, имена — непрозрачные хеши
│   ├── 04eee2e9ba8c.pdf
│   └── ...
├── master_ledger_2025.csv        реестр транзакций по всем заёмщикам, одна таблица
├── submission_template.json      список сценариев и пунктов с пустыми ячейками
└── ground_truth.json             необязательно: ключ для локального скоринга
```

Первые три обязательны — без них стадия останавливается и называет, чего не хватает.
`ground_truth.json` нужен только команде `score` и в решении не участвует.

Колонки леджера: `txn_id`, `date`, `account_id`, `counterparty`, `description`, `amount`,
`currency`. Расходы отрицательные, поступления положительные, часть сумм может быть пустой.
Заёмщика строки задаёт префикс идентификатора: `TXN-P1-0039` принадлежит сценарию `P1`.

**Документы раскладывать по папкам не нужно и переименовывать нельзя.** Все PDF лежат одной
кучей в `data/documents/`; что это за документ и к какому заёмщику он относится, агент
определяет сам на фазе 1 — по содержимому, а не по имени файла.

## Инфраструктура и настройки

Параметры читаются из `.env` в рабочем каталоге. Уже экспортированную переменную окружения файл
**не перекрывает**, поэтому случайный `export MODEL=...` в оболочке имеет приоритет. Минимум
для работы:

```bash
LLM_API_KEY=...
TEAM=your-team-name
CONTACT_EMAIL=you@example.com
MODEL=gemini-3.5-flash-lite
```

### Провайдер и модель

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_API_KEY` | ключ провайдера; читается и `GOOGLE_API_KEY` | — |
| `LLM_BASE_URL` | корень OpenAI-совместимого API | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `MODEL` | модель для всех стадий; она же в поле `model` submission | `gemini-3.5-flash-lite` |
| `REASONING_EFFORT` | `low\|medium\|high` или пусто | — |
| `LLM_SEED` | seed запроса или `none`; слой Gemini поля не принимает | `none` |

### Темп и устойчивость вызовов

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `RPM` | запросов в минуту | `14` |
| `RPH` | запросов в час; `0` — окна нет | `0` |
| `MAX_CONCURRENCY` | параллельных вызовов | `4` |
| `REQUEST_TIMEOUT` | секунд на один вызов; по истечении обрыв и повтор | `60` |

Планировщик держит оба окна сразу и берёт больший интервал: у Gemini часового окна нет
(`RPH=0`), темп задаёт `RPM`. Ставить `RPM` следует **чуть ниже** разрешённого тарифом: при
устойчивых отказах 429 клиент через две минуты ожидания на одном вызове считает, что кончилась
суточная квота, и гасит сеть до конца прогона.

Полный прогон с нуля — около 330 вызовов: 203 на триаж двухсот документов, остальное на
ковенанты, факты, разметку и критика ячеек. Чтобы поднять пропускную способность, поднимать
надо `RPM` и `MAX_CONCURRENCY` вместе: при четырёх потоках и секундной латентности потолок
упирается в параллелизм раньше, чем в лимит запросов.

### Поля submission

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TEAM` | поле `team` в submission | `halyk-agent` |
| `CONTACT_EMAIL` | поле `contact_email` | — |

### Пути и журналы

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATA_DIR` | каталог датасета | `./data` |
| `OUT_DIR` | результаты | `./out` |
| `ARTIFACTS_DIR` | артефакты стадий | `./artifacts` |
| `CACHE_DIR` | кэш страниц | `./.cache` |
| `DB` | путь к SQLite-стору | `./.cache/halyk.db` |
| `LOG_DIR` | журналы и дампы вызовов | `./logs` |
| `LOG_LEVEL` | `debug\|info\|warn\|error` — порог для stderr; в файл пишется всё | `info` |

### Состояние и кэш

Состояние живёт в SQLite (`.cache/halyk.db`): документы, страницы, транзакции, артефакты стадий,
вердикты и кэш ответов модели по хешу промпта. Отсюда два следствия:

- прерванный прогон продолжается с того же места и не тратит квоту заново;
- **изменение текста промпта обнуляет кэш этой стадии** — она пойдёт в сеть целиком.

Удалять `.cache/` стоит только осознанно: полный прогон с нуля стоит примерно 330 вызовов и
около сорока минут при `RPM=14`.

### Курсы валют

`config/fx.yaml` задаёт запасные курсы на случай, когда документы заёмщика курса не раскрывают.
Курс из факт-базы всегда главнее; применение запасного попадает в журнал отдельной строкой.

## Что получается на выходе

```
out/
├── submission.json    ответ по форме шаблона — то, что оценивается
├── audit.jsonl        по вердикту на строку: трасса, вклад, уверенность
├── review.md          ячейки на ручную проверку
└── report.pdf         человекочитаемое досье на весь прогон
```

Побочное состояние прогона — `artifacts/`, `.cache/`, `logs/` — описано в
[ARCHITECTURE.md](ARCHITECTURE.md#файловая-иерархия). Там же про
[эталон для сверки прогонов](ARCHITECTURE.md#эталон-для-сверки-прогонов) —
`testdata/reference-submission.json`, с которым сравнивается каждый новый прогон.

`report.pdf` собирается только из `out/submission.json` и стора, модель не вызывается, поэтому
отчёт можно перерисовывать сколько угодно. Внутри: сводка, таблица всех ячеек, по каждому
заёмщику — счета, связанные стороны, курсы, корректировки, итоги леджера, а на каждый пункт
статус, `actual`, выражение с порогом и периодом, термы, evidence с расшифровкой транзакции,
уверенность, реплика критика, цитата договора и трасса вычисления. Заканчивается приложением
«Cells to check by hand». Текстовый слой в PDF есть — по отчёту работают поиск и `pdftotext`.

```bash
bin/halyk-agent report --only P1,B4          # только эти заёмщики
bin/halyk-agent report --file /tmp/p1.pdf    # другой путь
```

## Дисклеймер датасета

Все данные набора вымышлены: заёмщики, контрагенты, аудиторы, договоры и все приведённые числа
созданы для конкурса. Ни один документ не отражает реального клиента, договор или операцию
какой-либо организации.
